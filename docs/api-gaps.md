# تقرير تحليل الفجوات البرمجية والتوصيات (API Gaps & Architectural Recommendations)

يقدم هذا التقرير تحليلاً معماريًا دقيقًا للفجوات التي تمت ملاحظتها أثناء مطابقة شاشات وتجربة مستخدم ClinicFlow مع عقود الـ Backend API الحالية، والحلول التي تم تطبيقها بالواجهة، وتوصيات التطوير المستقبلي.

---

## 1. الفجوات التي تمت معالجتها في الـ Frontend (Resolved in Frontend)

| الفجوة في الـ API / التصميم | السلوك في الـ Backend | المعالجة المنفذة في الـ Frontend |
|---|---|---|
| **حساب رقم الدور المتوقع لحظيًا** | الـ Backend يُنشئ رقم الدور ذريًا عند الحفظ (`SaveAppointment`) | أضافت الواجهة في نموذج الحجز استعلامًا فوريًا لآخر رقم دور لحجز نفس اليوم للطبيب لعرض `تذكرة الدور المتوقعة` للمريض قبل الضغط على تأكيد. |
| **التحقق من أهلية الاستشارة المجانية** | الـ Backend يرفض في الـ Validation إذا كان المريض متأخرًا عن صلاحية الاستشارة | أضافت الواجهة فحصًا مسبقًا لحالة المريض: إذا كان المريض متجاوزًا لتاريخ الاستشارة، تظهر نافذة تأكيد تسأل السكرتارية عما إذا كان هناك استثناء من الطبيب، مع تعديل السعر المحسوب تلقائيًا. |
| **تقارير تدقيق الأسعار الخاصة** | الـ Backend يمتلك جداول تسعير ولكن تقرير الاستخدام غير مجمع في نقطة نهاية واحدة | تم توفير واجهة تقرير تفاعلية تجمع حالات الخصومات المطبقة مع نسب الخصم وسبب التخفيض، مع إمكانية تصدير التقرير أو طباعته. |
| **منع بدء الكشف غير المسدد** | الـ Backend يمنع في `CompleteMedicalVisit` إنهاء الكشف إن كان `Unpaid` | قامت الواجهة بمنع الوصول المبكر والتحذير الفوري على شاشة الكشف للطبيب مع إغلاق أزرار التشخيص لمنع ضياع وقت الطبيب في فحص مريض لم يسدد بعد. |

---

## 2. توصيات معمارية لفريق الـ Backend (Recommendations for Future API Releases)

1. **إضافة SignalR / WebSockets لطابور الانتظار**:
   - حاليًا يعتمد الـ Frontend على إعادة التحميل والتحديث الدوري.
   - يوصى بإنشاء `QueueHub` لإرسال إشعارات فورية عند دخول مريض جديد أو تغيير ترتيب الطابور أو تغيير حالة الحجز، لتحديث شاشات الدكتور والاستقبال في أجزاء من الثانية.
2. **Batch Operations لتصاريح أطباء السكرتارية**:
   - دعم نقطة نهاية `PUT /api/{clinicSlug}/secretaries/{id}/doctor-permissions` تقبل مصفوفة معرفات دفعة واحدة (وهو ما تم دعمه بالفعل في الواجهة والـ DTO).
3. **Medical Attachments (المرفقات والملفات الطبية)**:
   - إضافة دعم لرفع صور الأشعة والتحاليل الطبية داخل شاشة الكشف السريري مع تخزين آمن ومشفر للملفات الطبية.
